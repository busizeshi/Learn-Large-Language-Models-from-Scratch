# 丰富的序列

容器序列：容器序列中可存放不同类型的项（item），其中包括嵌套容器。示例：list、tuple 和 collections.deque。

扁平序列：扁平序列中可存放简单类型的项（item）。示例：str、bytes 和 arrary.array。

> 容器序列中存放的是其所包含对象的引用，对象可以是任何类型；扁平序列中存放的是其所包含内容的
>值，而不是各自不同的 Python 对象

## 列表推导式与生成器表达式

这两个都是“从可迭代对象构建序列”的语法糖，区别在于：**列表推导式立即构建整个列表，生成器表达式惰性地逐个产出值**。

### 简单概述

#### 列表推导式（List Comprehension）

语法：`[表达式 for 变量 in 可迭代对象 (if 条件)]`

```python
# 基础：等价于 for 循环逐个 append
squares = [n * n for n in range(1, 6)]        # [1, 4, 9, 16, 25]

# 带过滤条件
even_squares = [n * n for n in range(1, 6) if n % 2 == 0]  # [4, 16]

# 条件表达式（三元），注意位置在 for 前面
labels = ['偶' if n % 2 == 0 else '奇' for n in range(5)]  # ['奇', '偶', '奇', '偶', '奇']

# 笛卡尔积 / 嵌套循环（for 从左到右依次嵌套）
pairs = [(x, y) for x in 'ab' for y in range(2)]
# [('a', 0), ('a', 1), ('b', 0), ('b', 1)]
```

等价的传统写法对比：

```python
squares = []
for n in range(1, 6):
    squares.append(n * n)
```

#### 生成器表达式（Generator Expression）

语法和列表推导式一样，只是**把方括号换成圆括号**：

```python
gen = (n * n for n in range(1, 6))

print(gen)           # <generator object ...> —— 此时还没计算任何值
print(next(gen))     # 1
print(next(gen))     # 4
print(list(gen))     # [9, 16, 25] —— 剩余的值
```

核心特性——**惰性求值，按需产出，不占大内存**：

```python
import sys

lst = [n * n for n in range(10_000_000)]
gen = (n * n for n in range(10_000_000))

print(sys.getsizeof(lst))   # ~90 MB 级别：所有值已在内存
print(sys.getsizeof(gen))   # ~200 字节：只存"怎么算"，不存结果
```

最典型用法——**作为聚合函数的唯一参数时，圆括号可省略**：

```python
total = sum(n * n for n in range(1_000_000))   # 逐个产出、逐个累加，全程低内存
has_negative = any(x < 0 for x in [1, -2, 3])
all_ready = all(x > 0 for x in [1, 2, 3])
```

#### 关键差异与选择

```python
lst = [n for n in range(3)]   # 列表：可反复遍历、可索引、len() 可用
gen = (n for n in range(3))   # 生成器：只能遍历一次，耗尽即空

print(sum(lst), sum(lst))     # 3 3  （可重复使用）
print(sum(gen), sum(gen))     # 3 0  （第二次已耗尽！）
```

选择建议：

| 场景 | 用哪个 |
|---|---|
| 需要多次遍历、索引、`len()` | 列表推导式 |
| 只遍历一次（sum/any/统计/写入文件） | 生成器表达式（省内存） |
| 数据量巨大或无限流 | 生成器表达式 |

#### 推导式作用域&海象运算符

**核心规则**：Python 3 里，列表推导式（Listcomp）、生成器表达式（Genexp）、集合/字典推导式中，在 `for` 子句里赋值的变量都只存在于**推导式自己的局部作用域**——推导式结束时它们就消失，不会泄漏到外部。

```python
>>> x = 'ABC'
>>> codes = [ord(x) for x in x]
>>> x        # ① 外部的 x 毫发无损，仍是 'ABC'
'ABC'
>>> codes
[65, 66, 67]
```

这行有两个 `x`，作用完全不同：

- `for x` 中的 `x` → **推导式内部的局部循环变量**
- `in x` 中的 `x` → **外部作用域的变量**，在推导式开始时立即求值

推导式内部"遮蔽"了外部 `x`，但结束后外部的 `x` 不受影响（①）。

> 对比：Python 2 的列表推导式会泄漏循环变量，`x` 会变成 `67`。Python 3 修复了这个问题。

**海象运算符 `:=` 的例外（PEP 572）**：由 `:=` 赋值的变量会**绑定到包含推导式的那层作用域**（函数或模块作用域），推导式结束后依然可访问，除非用 `global` / `nonlocal` 声明。

```python
>>> codes = [last := ord(c) for c in x]
>>> last     # ② 依然可以访问，值为最后一次循环写入的 67
67
>>> c        # ③ 普通循环变量，只活在推导式内部
Traceback (most recent call last):
  ...
NameError: name 'c' is not defined
```

| 写法 | 行为 |
|---|---|
| 推导式内 `=` 赋值 | 类似函数局部变量，出作用域即消失 |
| 推导式内 `:=` 赋值 | "穿透"到外层函数/模块作用域，保留下来 |

这样设计的动机是在推导式里**复用中间计算结果**，避免重复调用：

```python
data = [-2, 5, -1, 8]

# 不用 walrus：f(v) 要算两遍
results = [f(v) for v in data if f(v) > 0]

# 用 walrus：只算一遍，且循环结束后还能拿到最后一个满足条件的值
results = [y for v in data if (y := f(v)) > 0]
```

**延伸注意点**：列表推导式立即全部求值；生成器表达式只有**最外层可迭代对象**在定义时求值，其余部分惰性求值：

```python
x = 10
lst = [x * n for n in range(3)]   # 立即求值 → [0, 10, 20]
gen = (x * n for n in range(3))   # range(3) 立即求值，x 暂不取
x = 5
print(lst)        # [0, 10, 20]
print(list(gen))  # [0, 5, 10] —— x 是惰性取的新值！
```

一句话总结：**推导式像一个小函数，内部变量与外界隔离；唯独 `:=` 的目标变量会留在"外面的那层"作用域里**。

### 列表推导式与 filter 和 map 比较

#### filter 和 map 的基本用法

两者都是内置的**惰性迭代器**（Python 3 中不立即计算）：

```python
map(转换函数, 可迭代对象)      # 对每一项应用函数 → 产出结果
filter(判定函数, 可迭代对象)   # 函数返回真值 → 保留该项；否则丢弃
```

```python
words = ['apple', 'fig', 'banana', 'kiwi']

# map：逐项转换（这里把每个词变大写）
upper = map(str.upper, words)
print(upper)              # <map object ...> —— 惰性，还没计算
print(list(upper))        # ['APPLE', 'FIG', 'BANANA', 'KIWI']

# filter：逐项判定（保留长度 > 3 的词）
long = filter(lambda w: len(w) > 3, words)
print(list(long))         # ['apple', 'banana', 'kiwi']

# filter 的判定函数返回 "真值" 即可，不必是布尔值
# 若传 None，则保留所有真值项：filter(None, [0, 1, '', 'a', None]) → [1, 'a']
```

#### 用列表推导式实现同样的功能

推导式把"过滤"和"转换"写在一行里：**表达式部分 ≈ map，`if` 部分 ≈ filter**。

```python
# 对应 map(str.upper, words)
print([w.upper() for w in words])          # ['APPLE', 'FIG', 'BANANA', 'KIWI']

# 对应 filter(lambda w: len(w) > 3, words)
print([w for w in words if len(w) > 3])    # ['apple', 'banana', 'kiwi']
```

#### 两者组合：真正的对比

任务：**保留长度 > 3 的词，并转成大写**。

```python
# 写法 1：filter + map 串联（由内向外读）
r1 = list(map(str.upper, filter(lambda w: len(w) > 3, words)))
print(r1)   # ['APPLE', 'BANANA', 'KIWI']

# 写法 2：列表推导式（从左到右读，表达式放在最后）
r2 = [w.upper() for w in words if len(w) > 3]
print(r2)   # ['APPLE', 'BANANA', 'KIWI']

assert r1 == r2
```

多步转换的场景差异更明显——把每个数加 10 再开方，只要正的偶数：

```python
import math
nums = [1, 2, 3, 4, 5, 6]

# map/filter 风格：一层套一层，从内往外剥
r1 = list(map(lambda n: round(math.sqrt(n + 10), 2),
              filter(lambda n: n % 2 == 0, nums)))

# 推导式：主循环一目了然，转换逻辑集中在最前面
r2 = [round(math.sqrt(n + 10), 2) for n in nums if n % 2 == 0]

print(r1)   # [4.47, 4.9, 5.29]
print(r2)   # [4.47, 4.9, 5.29]
```

> 阅读顺序的区别：`map(f, filter(cond, data))` 的执行顺序是 **data → filter → map**，但代码要从内往外读；推导式 `[f(x) for x in data if cond(x)]` 从左到右正好是"先过滤、最后转换"，跟直觉一致。

#### 同一任务的三种写法（含基准写法）

```python
nums = [1, 2, 3, 4, 5]

# ① 传统 for 循环：最啰嗦，但步骤最直白
result = []
for n in nums:
    if n % 2:
        result.append(n * n)

# ② map + filter + lambda：函数式风格，但 lambda 噪音大
result = list(map(lambda n: n * n, filter(lambda n: n % 2, nums)))

# ③ 列表推导式：Python 社区主流选择
result = [n * n for n in nums if n % 2]
```

#### 怎么选（含性能）

| 维度 | map / filter | 列表推导式 |
|---|---|---|
| 过滤 + 转换组合 | 需要嵌套串联，从内向外读 | 一行完成，从左到右读 |
| 需要 lambda 时 | 可读性差、更啰嗦 | 明显更清晰 |
| 函数已存在（如 `str.upper`、`int`） | **更合适**，循环在 C 层执行，通常略快 | 也很好，只是每项多一次方法调用 |
| 返回类型 | 惰性迭代器（Python 3） | listcomp 立即建列表；genexp 惰性 |
| 社区风格 | 偏函数式代码库 | PEP 8 / Fluent Python 推荐 |

```python
# 推荐：函数现成，直接 map，干净又快
list(map(int, ['1', '2', '3']))        # [1, 2, 3]
list(map(str.upper, words))

# 推荐：涉及条件/自定义逻辑，用推导式
[n * n for n in nums if n % 2]

# 不推荐：为 map 专门造 lambda
list(map(lambda w: w.upper(), words))  # 不如 [w.upper() for w in words]
```

一句话总结：**转换函数已经存在时 `map`/`filter` 很顺手；一旦需要 lambda 或要"边过滤边转换"，列表推导式几乎总是更好读**。性能差异通常很小，可读性才是首要标准。

## 元组不仅仅是不可变列表

元组有双重用途：既可用作不可变列表，又可用作没有字段名的记录（record）。

### 将元组用作记录

元组的第二重身份是**记录（record）**：元组中的每一项（item）保存一个字段的数据，**项的位置决定了数据的含义**。

这一点与"不可变列表"的用法正好相反，两种用途对"项数"和"顺序"的要求也完全不同：

| 用途 | 项数 | 顺序 | 原因 |
|---|---|---|---|
| 不可变列表 | 通常不固定 | 不重要 | 所有项是**同类**东西的集合，多一个少一个、怎么排列都不改变语义，排序是安全的 |
| 记录 | 固定 | 重要 | 每一项是**不同**的字段，位置即含义；一旦排序，字段含义就会错位，信息被破坏 |

例如 `(33.9425, -118.408056)` 的含义是"（纬度， 经度）"——若对它排序，坐标就失去意义了。

```python
# 记录 1：洛杉矶国际机场的经纬度（纬度在前、经度在后——位置即含义）
lax_coordinates = (33.9425, -118.408056)

# 记录 2：一条赋值语句把元组的 5 个字段分别解包给 5 个变量
# 字段依次为：市名、年份、人口（千）、人口变化（%）、面积（km²）
city, year, pop, chg, area = ('Tokyo', 2003, 32_450, 0.66, 8014)

# 记录 3：一个 list，每项是一条 (国家代码, 护照号) 记录
traveler_ids = [('USA', '31195855'), ('BRA', 'CE342567'), ('ESP', 'XDA205856')]
```

"按位置读取字段"的惯用手段是**元组解包（tuple unpacking）**，上面的示例出现了三种形式：

```python
# 形式 1：并行赋值——左侧变量个数与元组字段数一致，按位置一一绑定
city, year, pop, chg, area = ('Tokyo', 2003, 32_450, 0.66, 8014)

# 形式 2：% 运算符——把元组中的每一项视为独立字段，填入字符串中对应的占位符（%s）
for passport in sorted(traveler_ids):
    print('%s/%s' % passport)
# BRA/CE342567
# ESP/XDA205856
# USA/31195855

# 形式 3：for 循环头部——循环变量写成元组模式，自动按位置解包每条记录
for country, _ in traveler_ids:
    print(country)
# USA
# BRA
# ESP
```

- 形式 2 中，`'%s/%s' % passport` 要求右边的元组"字段数 = 占位符数"——这正是把元组当记录用的体现；
- 形式 3 中，`for` 知道如何获取元组中的每一项并按位置绑定；对第二项（护照号）不感兴趣，就赋给**虚拟变量 `_`**。

> `_` 的三个身份：
>
> 1. **惯例**：表示"占位、不使用"的虚拟变量；
> 2. **match/case 语句**：`_` 是通配符，匹配任何值但**不绑定**它；
> 3. **Python 控制台**：上一条命令的结果若不是 `None`，会被自动赋给 `_`。

为什么"没必要为了给字段命名而专门创建一个类"：

- 上面三种用法**全程没有用索引**，只靠解包就访问到了每个字段——接收解包的变量名（`city`、`country`）本身就是"字段名"；
- 若连索引都不用、只靠解包访问字段，就更没必要建类了；
- 只有确实需要"用名字访问字段"时，才值得引入具名字段的结构。"五 数据类构建器"会介绍两种创建**具名字段（named fields）元组**的方法。

> 术语演变：大多数程序员说"元组解包"，但"**可迭代对象解包**（iterable unpacking）"的说法正在增多（见 PEP 3132 —— Extended Iterable Unpacking）。下一节将深入介绍元组、序列以及一般可迭代对象的解包。

### 将元组用作不可变列表

Python 解释器和标准库经常把 tuple 当作不可变的 list 使用，好处有两点，且互为因果：

1. **意图清晰**：源码中出现 tuple，读代码的人立刻知道它的长度永远不会变——不可变本身就是一种"文档"；
2. **性能优越**：正因为"长度固定、内容不可变"，Python 才有条件对 tuple 做专门优化（见下文）。

#### 陷阱：不可变性是"相对的"

关键概念：**tuple 的不可变性只约束它存放的引用**——引用不可删除、不可替换；但引用指向的**对象本身**若是可变的，对象一被原地修改，元组的"值"就跟着变。

因果链条：

> 元组只保证"引用始终指向同一批对象" → 引用的对象可变 → 对象被原地修改 → 元组的值随之变化 → 相等性 / 哈希不稳定 → 潜在 BUG

```python
a = (10, 'alpha', [1, 2])
b = (10, 'alpha', [1, 2])
a == b             # True：此刻两个元组的值相等

b[-1].append(99)   # 注意：没有改动元组 b 本身，只改了它引用的 list
a == b             # False：b 的"值"变了（a 引用的是另一个 list，没受影响）
b                  # (10, 'alpha', [1, 2, 99])
```

这个现象的后果（为什么说"在元组中存放可变对象可能导致 BUG"）：

- 只有**值不会改变**的对象才是可哈希（hashable）的；
- 含可变项的元组值会变 → 不可哈希 → **不能作为 dict 的键，也不能放入 set**；
- 更隐蔽的是：即便此刻能哈希，只要内部可变对象将来被修改，哈希值就失效了。

利用内置 `hash()` 可以写一个小函数，探测"值是否不可变"（能哈希 ≈ 值不可变）：

```python
def fixed(o):
    try:
        hash(o)
    except TypeError:
        return False
    return True

tf = (10, 'alpha', (1, 2))   # 内部全是不可变对象
tm = (10, 'alpha', [1, 2])   # 内部含 list

fixed(tf)   # True  —— 可哈希
fixed(tm)   # False —— 不可哈希
```

> 判定规则一句话：**元组可哈希 ⇔ 它的所有项都可哈希**。

#### 性能优势从哪来（Raymond Hettinger 的总结）

下表每一条优势，根源都是同一个前提——"长度固定、内容不可变"：

| 优势 | 因果解释 |
|---|---|
| 字面量编译为常量 | 元组字面量在编译期被当成**一个整体常量**，一次操作即可生成字节码；列表字面量要把每个元素当独立常量逐个推入堆栈，再执行"构建列表"的指令 |
| `tuple(t)` 不复制 | 不可变 → 无需副本，直接返回 `t` 的引用；`list(l)` 必须创建副本（列表随时可能被就地修改） |
| 内存精确分配 | 长度固定 → 分配的空间**正好够用**；list 为支持随时 `append`，会**预分配**多余空间 |
| CPU 缓存友好 | 元组把各项的引用（指针）直接存在**自身内部数组**中，结构连续；list 只保存一个指向"另一个独立引用数组"的指针，数组可与列表结构分离存放。列表增长超过容量时需重新分配更大的数组 → CPU 缓存效率降低 |

### 元组与列表中的方法比较

当把元组当作"不可变列表"使用时，有必要了解二者 API 的差异。核心结论一句话：

**元组支持所有"不涉及增、删项"的 list 方法；另外元组没有 `__reversed__` 方法，但 `reversed(my_tuple)` 依然正常工作**（内置函数 `reversed()` 会退回使用 `__len__` + `__getitem__` 实现反向迭代）。

按"为什么元组有 / 没有"给方法分组，比死记硬背更牢靠：

| 分组 | 方法 | 列表 | 元组 | 原因 |
|---|---|---|---|---|
| 只读 / 查询 | `__getitem__`、`__contains__`（`e in s`）、`__iter__`、`__len__`、`count(e)`、`index(e)` | • | • | 只读不写，与不可变不冲突 |
| 拼接 / 重复 | `__add__`（`s+s2`）、`__mul__` / `__rmul__`（`s*n`） | • | • | 生成**新**对象，不改原对象 |
| 写：增 | `append`、`extend`、`insert`、`__iadd__`（`s+=s2`） | • | ✗ | 就地增项，违反不可变 |
| 写：删 | `remove`、`pop`、`clear`、`__delitem__` | • | ✗ | 就地删项，违反不可变 |
| 写：改 / 排 | `__setitem__`、`sort`、`reverse`、`__imul__` | • | ✗ | 就地改项 / 排序，违反不可变 |
| 拷贝 | `copy` | • | ✗ | 元组本就不可变，浅拷贝无意义 |
| 仅元组 | `__getnewargs__` | ✗ | • | 支持 pickle 优化序列化 |
| 反向迭代 | `__reversed__` | • | ✗ | 但内置函数 `reversed(t)` 仍可用 |

一句话总结：**tuple 的 API ≈ list 的 API 去掉全部"写"方法**——这正是不变性在接口层面的直接体现。

> 元组双重身份速记：**记录**（项数固定、位置即含义、靠解包访问字段）+ **不可变列表**（顺序不重要、享有常量编译 / 按引用返回 / 精确分配 / 缓存友好等优化）；不可变性约束的是**引用**而非**值**，含可变项的元组不可哈希。
