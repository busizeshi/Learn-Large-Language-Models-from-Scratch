# 数据类构建器

> 本章主题：**用最少的样板代码，构建「以数据为中心」的简单类**
>
> 「数据类就像孩子。作为一个起点，它们是可以的，但要作为一个成年对象参与整个系统的工作，它们需要承担一些责任。」——Martin Fowler 与 Kent Beck（《重构：改善既有代码的设计》第 1 版）
>
> 本章是《流畅的 Python》第 2 版新增的重磅章节。Python 提供了三种构建「数据类」（只作为字段集合的简单类）的快捷方式：`collections.namedtuple`、`typing.NamedTuple` 和 `@dataclasses.dataclass`。它们能自动生成 `__init__`、`__repr__`、`__eq__` 等样板方法，让你少写重复代码。本章依次讲解：三种构建器的横向对比、类型提示（Type Hints）入门（PEP 526）、@dataclass 的全部常用选项（frozen、order、field、ClassVar、InitVar）、一个警告（数据类可能是一种「代码异味」），以及用模式匹配（Pattern Matching）拆解任意类实例的技巧。

## 学习地图：本章知识脉络

先建立全局视图——三种构建器的定位与递进关系：

```
      简易/历史 ──────────────────────────────────────────▶ 强大/现代

 collections.namedtuple     typing.NamedTuple        @dataclasses.dataclass
 （Python 2.6+，工厂函数）   （3.5+，类型提示/元类）    （3.7+，装饰器，功能最全）
      │                          │                          │
   tuple 子类，不可变         tuple 子类，不可变         普通类，默认可变
   轻量记录                   带类型的轻量记录            默认值工厂、验证、
                                                          冻结、排序、ClassVar……
```

一句话记住本质区别：**前两者是 tuple 的子类（不可变、可解包、能按位置索引）；@dataclass 只是装饰器，不影响类的继承结构（默认可变、可定制性最强）**。

全章 10 节可压缩为 5 条主线，按顺序学即可：

1. **概念层**：什么是数据类、三种构建器横向对比（5.1–5.2 节）
2. **工具层**：collections.namedtuple → typing.NamedTuple → @dataclass 逐级进阶（5.3–5.6 节）
3. **基础层**：类型提示（Type Hints）与 PEP 526 变量注解语法（5.5 节，穿插其中）
4. **设计层**：数据类是双刃剑——何时是脚手架、何时是代码异味（5.7 节）
5. **应用层**：用类模式（Class Pattern）对任意类实例做模式匹配（5.8 节）

## 一、数据类与三种构建器（5.1–5.2 节）

### 1.1 什么是「数据类」

「数据类」是一种编码模式：**只作为字段集合、几乎没有额外功能的简单类**。其他语言里的对等物如 Java 的 POJO、Kotlin 的 data class。Python 里有三个专门的类构建器：

| 构建器 | 登场版本 | 形态 | 特点 |
|--------|:---:|------|------|
| `collections.namedtuple` | 2.6 | 工厂函数 | 最简单，构建 tuple 子类 |
| `typing.NamedTuple` | 3.5（3.6 起支持 class 语法） | 类语法 | 带类型提示的具名元组 |
| `@dataclasses.dataclass` | 3.7 | 类装饰器 | 功能最全、定制性最强 |

> 书外补充：`typing.TypedDict` 看起来像第四种数据类构建器（语法与 NamedTuple 类似，文档里也紧挨着），但它**不会构建可实例化的类**——它只是为「用字典存记录」的代码提供类型提示的语法（详见第 15 章）。

### 1.2 朴素类的问题

不用任何构建器，手写一个坐标类：

```python
class Coordinate:
    def __init__(self, lat, lon):
        self.lat = lat
        self.lon = lon
```

两个问题：`__init__` 样板代码每个属性要写 3 次（形参、赋值、self.xxx）；从 object 继承的功能非常粗糙：

```python
>>> moscow = Coordinate(55.76, 37.62)
>>> moscow
<coordinates.Coordinate object at 0x107142f10>    # __repr__ 无用
>>> location = Coordinate(55.76, 37.62)
>>> location == moscow
False                                              # __eq__ 比较的是对象 ID
>>> (location.lat, location.lon) == (moscow.lat, moscow.lon)
True                                               # 想比内容得手动逐字段比较
```

### 1.3 三种构建器一瞥

同一个坐标类，三种写法（后两种的类主体几乎完全相同，只差 class 语句本身）：

```python
# ① collections.namedtuple：工厂函数
from collections import namedtuple
Coordinate = namedtuple('Coordinate', 'lat lon')
issubclass(Coordinate, tuple)                  # True
moscow = Coordinate(55.756, 37.617)
moscow                                         # Coordinate(lat=55.756, lon=37.617)
moscow == Coordinate(lat=55.756, lon=37.617)   # True

# ② typing.NamedTuple：支持类型提示
import typing
Coordinate = typing.NamedTuple('Coordinate', [('lat', float), ('lon', float)])
typing.get_type_hints(Coordinate)   # {'lat': <class 'float'>, 'lon': <class 'float'>}
# 也支持关键字参数形式：typing.NamedTuple('Coordinate', lat=float, lon=float)

# ③ typing.NamedTuple 的 class 语法（3.6+）：可读性最好，还能加方法
from typing import NamedTuple

class Coordinate(NamedTuple):
    lat: float
    lon: float

    def __str__(self):
        ns = 'N' if self.lat >= 0 else 'S'
        we = 'E' if self.lon >= 0 else 'W'
        return f'{abs(self.lat):.1f}°{ns}, {abs(self.lon):.1f}°{we}'

# ④ @dataclass：类主体与 ③ 相同，只是换成装饰器
from dataclasses import dataclass

@dataclass(frozen=True)
class Coordinate:
    lat: float
    lon: float
    # __str__ 同 ③
```

> **记忆要点**：`class Coordinate(NamedTuple)` 中，NamedTuple 出现在**超类的位置，但它并不是超类**——typing.NamedTuple 是通过元类（MetaClass）来定制类的创建的。验证：`issubclass(Coordinate, typing.NamedTuple)` 是 `False`，而 `issubclass(Coordinate, tuple)` 是 `True`。
>
> 相对地，`@dataclass` **完全不依赖继承或元类**——Coordinate 只是 object 的子类。所以即使你已经在用继承体系或元类，@dataclass 也不会与之冲突。

### 1.4 三种构建器对比（重绘表 5.1）

设 x 为数据类实例：

| 功能 | namedtuple | NamedTuple | dataclass |
|------|-----------|------------|-----------|
| 可变实例 | NO | NO | **YES**（默认） |
| class 语句语法 | NO | YES | YES |
| 构造字典 | `x._asdict()` | `x._asdict()` | `dataclasses.asdict(x)` |
| 获取字段名 | `x._fields` | `x._fields` | `[f.name for f in dataclasses.fields(x)]` |
| 获取默认值 | `x._field_defaults` | `x._field_defaults` | `[f.default for f in dataclasses.fields(x)]` |
| 获取字段类型 | N/A | `x.__annotations__` | `x.__annotations__` |
| 更改后建新实例 | `x._replace(**kw)` | `x._replace(**kw)` | `dataclasses.replace(x, **kw)` |
| 运行时动态建类 | `namedtuple(...)` | `NamedTuple(...)` | `dataclasses.make_dataclass(...)` |

> **记忆要点**：
> - 最关键的差异是**可变性**——具名元组是 tuple 子类所以不可变；@dataclass 默认可变，`frozen=True` 可冻结；
> - 获取字段类型别直接读 `__annotations__`，推荐 `inspect.get_annotations(MyClass)`（3.10+）或 `typing.get_type_hints(MyClass)`（3.5–3.9）——它们能解析前向引用（Forward Reference）等额外服务；
> - 三种构建器都是用**元编程技术**把方法和数据属性注入到类中，只是手段不同（工厂函数 / 元类 / 装饰器）。

## 二、collections.namedtuple：最经典的具名元组（5.3 节）

### 2.1 定义与使用

`namedtuple(类名, 字段名列表)` 是工厂函数，用于构建带字段名、类名和详细 `__repr__` 的 tuple 子类：

```python
>>> from collections import namedtuple
>>> City = namedtuple('City', 'name country population coordinates')   # ①
>>> tokyo = City('Tokyo', 'JP', 36.933, (35.689722, 139.691667))       # ②
>>> tokyo
City(name='Tokyo', country='JP', population=36.933, coordinates=(35.689722, 139.691667))
>>> tokyo.population        # ③ 按字段名访问
36.933
>>> tokyo.coordinates
(35.689722, 139.691667)
>>> tokyo[1]                # ③ 也能按位置访问（本质是 tuple）
'JP'
```

- ① 字段名列表可以是「空格分隔的单个字符串」或「可生成多个字符串的可迭代对象」；
- ② **字段值必须逐个作为位置参数传入**（对比：tuple 构造函数只接受单个可迭代对象）；
- ③ 可按字段名或位置访问字段。

两个实用事实：**具名元组实例占用的内存与 tuple 完全相同**（字段名存储在类上，不在实例里）；作为 tuple 子类，它继承了 `__eq__`、`__lt__` 等比较方法，所以由 City 实例构成的列表可以直接 `sorted()`。

### 2.2 最有用的属性与方法

```python
>>> City._fields                              # 类属性：字段名元组
('name', 'country', 'population', 'coordinates')
>>> delhi_data = ('Delhi NCR', 'IN', 21.935, Coordinate(28.613889, 77.208889))
>>> delhi = City._make(delhi_data)            # 类方法：从可迭代对象构建，等价 City(*delhi_data)
>>> delhi._asdict()                           # 实例方法：转成 dict（键=字段名，值=字段值）
{'name': 'Delhi NCR', 'country': 'IN', 'population': 21.935,
 'coordinates': Coordinate(lat=28.613889, lon=77.208889)}
>>> import json
>>> json.dumps(delhi._asdict())               # 转 dict 后即可 JSON 序列化
'{"name": "Delhi NCR", "country": "IN", "population": 21.935, "coordinates": [28.613889, 77.208889]}'
```

> 版本细节：`_asdict()` 在 Python 3.7 及以前返回 OrderedDict；3.8 起返回普通 dict（因为 3.7 起 dict 保证插入顺序）。必须用 OrderedDict 时，自行 `OrderedDict(x._asdict())`。

### 2.3 默认值：defaults 参数

Python 3.7 起，namedtuple 接受 `defaults` 关键字参数——一个可产生 N 项的可迭代对象，为**最右边的 N 个字段**提供默认值：

```python
>>> Coordinate = namedtuple('Coordinate', 'lat lon reference', defaults=['WGS84'])
>>> Coordinate(0, 0)
Coordinate(lat=0, lon=0, reference='WGS84')
>>> Coordinate._field_defaults
{'reference': 'WGS84'}
```

### 2.4 方法注入：为 namedtuple 添加方法（书中的 hack 附注）

collections.namedtuple 没有 class 语法，加方法要用「注入」这个小技巧：

```python
>>> Card = collections.namedtuple('Card', ['rank', 'suit'])
>>> Card.suit_values = dict(spades=3, hearts=2, diamonds=1, clubs=0)   # 附加类属性
>>> def spades_high(card):                                             # 先定义普通函数
...     rank_value = FrenchDeck.ranks.index(card.rank)
...     suit_value = card.suit_values[card.suit]
...     return rank_value * len(card.suit_values) + suit_value
>>> Card.overall_rank = spades_high                                    # 再赋值为类属性 → 变成方法
>>> lowest_card = Card('2', 'clubs')
>>> lowest_card.overall_rank()                                         # 注入成功
0
```

被注入的函数第一个参数不必叫 self——作为方法调用时它照样会拿到接收者。这是动态语言强大的体现（Ruby 中叫方法注入），但**不适用于内置类型（str、list 等）**——好在 Python 有这个限制，是件幸事。需要给具名元组加方法时，更推荐直接使用 typing.NamedTuple / @dataclass 的 class 语法。

## 三、typing.NamedTuple 与类型提示入门（5.4–5.5 节）

### 3.1 带类型的具名元组

```python
from typing import NamedTuple

class Coordinate(NamedTuple):
    lat: float                        # ① 每个实例字段都必须指定类型提示
    lon: float
    reference: str = 'WGS84'          # ② 类型提示 + 字段默认值
```

它与 collections.namedtuple 生成的类非常相似（方法和 tuple 继承完全相同），唯一区别是多了 `__annotations__` 类属性来保存字段类型——**而这个属性在运行时被 Python 忽略**，因为类型提示仅在编译时（被静态检查器）使用。

### 3.2 第一课：类型提示在运行时无效

```python
>>> class Coordinate(typing.NamedTuple):
...     lat: float
...     lon: float
>>> trash = Coordinate('Ni!', None)      # 运行时完全不检查！
>>> print(trash)
Coordinate(lat='Ni!', lon=None)
```

类型提示应理解为「**供 IDE 和类型检查器验证类型的文档**」。要看到效果，必须使用静态分析工具（Mypy、PyCharm 内置检查器）——它们只检查静态源代码，不检查运行中的代码：

```
$ mypy nocheck_demo.py
nocheck_demo.py:8: error: Argument 1 to "Coordinate" has incompatible type "str"; expected "float"
nocheck_demo.py:8: error: Argument 2 to "Coordinate" has incompatible type "None"; expected "float"
```

> **记忆要点**：Python 是动态语言——类型提示**不影响运行时行为**。它们的价值：① Mypy 等工具能提前发现错误；② IDE 提供更好的补全与提示；③ 让代码自文档化。

### 3.3 变量注解语法（PEP 526）

typing.NamedTuple 与 @dataclass 都使用 PEP 526 定义的变量注解（Variable Annotation）语法：

```python
var_name: some_type                 # 只有类型提示
var_name: some_type = a_value       # 类型提示 + 默认值（在数据类中会成为字段默认值）
```

定义数据类时最有用的三种类型：

1. **具体类**：如 `str`、`int`、`FrenchDeck`；
2. **参数化容器**：如 `list[int]`、`tuple[str, float]`；
3. **Optional**：如 `Optional[str]`——声明「可以是 str 或 None」的字段。

书外补充：Python 3.9+ 内置容器可直接用 `[]` 泛型语法（如 `list[str]`）；3.8 及以前须从 typing 导入 `List[str]`。Python 3.10+ 还可用 `str | None`（PEP 604）替代 `Optional[str]`。

### 3.4 「变量注解意义」：三个类的对照实验

类型提示运行时无效，但**解释器在 import 模块时会读取它们构建 `__annotations__` 字典**——typing.NamedTuple 与 @dataclass 正是用这个字典来增强类的。三个对照类说清一切：

```python
# ① 普通类：注解只是"记录"
class DemoPlainClass:
    a: int                 # 进入 __annotations__，但不创建类属性 a
    b: float = 1.1         # 有绑定值 → 成为类属性
    c = 'spam'             # 无注解 → 只是普通类属性

>>> DemoPlainClass.__annotations__
{'a': <class 'int'>, 'b': <class 'float'>}
>>> DemoPlainClass.a
AttributeError: type object 'DemoPlainClass' has no attribute 'a'    # a 不存在！
>>> DemoPlainClass.b
1.1
```

```python
# ② typing.NamedTuple：注解字段 → 只读实例属性
import typing

class DemoNTClass(typing.NamedTuple):
    a: int                     # 实例属性，无默认值（实例化时必须传）
    b: float = 1.1             # 实例属性，默认值 1.1
    c = 'spam'                 # 普通类属性

>>> DemoNTClass.a
<_collections._tuplegetter object at 0x101f0f940>     # 描述符（Descriptor）
>>> DemoNTClass.b
<_collections._tuplegetter object at 0x101f0f8b0>
>>> DemoNTClass.c
'spam'
>>> DemoNTClass.__doc__
'DemoNTClass(a, b)'
>>> nt = DemoNTClass(8)        # a 无默认值必须传；b 可省略
>>> nt.a, nt.b, nt.c
(8, 1.1, 'spam')               # nt.c 是从类上检索到的
```

a、b 是**描述符（Descriptor）**——可以理解成「属性读取器」：一种不需要显式调用 `()` 就能获取实例属性的方法。因此 a、b 是**只读的实例属性**——毕竟 NamedTuple 实例本质上是一种高级 tuple，而 tuple 不可变。尝试给 `nt.a` 赋值会引发 AttributeError。

```python
# ③ @dataclass：注解字段 → 可读写实例属性
from dataclasses import dataclass

@dataclass
class DemoDataClass:
    a: int
    b: float = 1.1
    c = 'spam'

>>> DemoDataClass.__annotations__
{'a': <class 'int'>, 'b': <class 'float'>}
>>> DemoDataClass.__doc__
'DemoDataClass(a: int, b: float = 1.1)'     # 注意：docstring 比 NamedTuple 多带类型提示
>>> DemoDataClass.a
AttributeError: type object 'DemoDataClass' has no attribute 'a'    # 类上没有 a！
>>> DemoDataClass.b
1.1                                          # b 是类属性，保存实例属性的默认值
>>> dc = DemoDataClass(9)
>>> dc.a = 10                # 可变（未 frozen）
>>> dc.b = 'oops'            # 运行时不做类型检查
>>> dc.z = 'secret stash'    # 还能动态添加属性
```

> **记忆要点**（注解在三种类中的行为差异）：
> - **普通类**：`a: int` 只是 `__annotations__` 里的记录，不会创建属性；有绑定值才有类属性；
> - **NamedTuple**：注解字段 → 描述符控制的**只读实例属性**；
> - **dataclass**：注解字段 → **可读写实例属性**（除非 frozen），类属性 b 仅用于保存默认值；
> - 三者中「无注解直接赋值」的属性（如 c），永远是普通类属性，被所有实例共享。

## 四、@dataclass 详解（5.6 节）

### 4.1 装饰器参数全表

```python
@dataclass(*, init=True, repr=True, eq=True, order=False, unsafe_hash=False, frozen=False)
```

（第一个位置上的 `*` 表示后面全是关键字参数）

| 参数 | 作用 | 默认值 | 备注 |
|------|------|:---:|------|
| `init` | 生成 `__init__` | True | 若用户自己实现了，则忽略该参数 |
| `repr` | 生成 `__repr__` | True | 同上 |
| `eq` | 生成 `__eq__` | True | 同上 |
| `order` | 生成 `__lt__`、`__le__`、`__gt__`、`__ge__` | False | 设为 True 时，若 eq=False 或自定义/继承了比较方法，会抛异常 |
| `unsafe_hash` | 生成 `__hash__` | False | 语义复杂，有多个问题需要注意，慎用 |
| `frozen` | 让实例不可变 | False | 用模拟方式实现不可变，并非真正不可变 |

日常最常改的只有两个：

- **`frozen=True`**：防止意外更改实例（赋值/删除字段时抛 `FrozenInstanceError`——AttributeError 的子类）。注意：@dataclass 是通过生成 `__setattr__` 和 `__delattr__` 来模拟不变性的，多事的程序员想绕过并不难，但在代码审查阶段很容易发现；
- **`order=True`**：允许排序数据类实例。

**`__hash__` 的生成规则**（重要且常被忽略）：

- `eq=True` 且 `frozen=True` → 生成合适的 `__hash__`（用所有字段计算，通过 field 选项也排除不了）→ 实例**可哈希**，能进 set、当 dict 键；
- `frozen=False`（默认）→ `__hash__` 被设为 None，实例**不可哈希**（覆盖了超类中的 `__hash__`）；
- `unsafe_hash=True` → 强制生成 `__hash__`。PEP 557 原话：「不建议这么做。若一个类在逻辑上是不可变的，但事实上是可变的，则可以这么做。但这是特殊的用例，应小心谨慎。」

> 书外补充（现代 Python 的增强）：
> - **`slots=True`**（3.10+）：让 dataclass 生成 `__slots__`，实例不再有 `__dict__`，更省内存、属性访问更快；
> - **`kw_only=True`**（3.10+）：强制所有字段只能用关键字参数传递，摆脱「默认值字段必须排在无默认值字段之后」的约束；
> - **`match_args=True`**（3.10+，默认开启）：控制是否为类生成 `__match_args__`（供位置类模式使用，见第六节）；
> - `weakref_slot=True`（3.11+）：让 slots 化的实例支持弱引用。

### 4.2 字段级定制：field() 与可变默认值陷阱

通过类型提示给字段默认值很直接，但有两条规则要牢记：

**规则一：默认值字段之后，其余字段都必须有默认值。** 因为 Python 不允许「有缺省值的参数」后面出现「没有缺省值的参数」——声明的实例字段会成为生成 `__init__` 的参数。

**规则二：可变默认值必须用 default_factory。** @dataclass 会直接拒绝 `= []` 的写法：

```python
@dataclass
class ClubMember:
    name: str
    guests: list = []       # 加载该类的模块即报错！
# ValueError: mutable default <class 'list'> for field guests is not allowed: use default_factory
```

正确写法：

```python
from dataclasses import dataclass, field

@dataclass
class ClubMember:
    name: str
    guests: list = field(default_factory=list)          # 每次实例化无参调用 list() → 新的空列表
    # 更精确的版本（3.9+）：规定 list 的每一项必须是 str
    # guests: list[str] = field(default_factory=list)
```

`default_factory` 的值可以是函数、类或任何其他可调用对象；**每次创建数据类实例时，都会（不带参数）调用它**，为字段生成默认值——这样每个实例拥有自己的 list，而不是所有实例共享类里的同一个。

> **记忆要点**：可变默认值（list/dict/set）是经典的 bug 来源（详见第 6 章「不要使用可变类型作为参数的默认值」）。@dataclass **只会拦截 list/dict/set 这三种**，其他可变对象不会引起它的注意——你必须自觉使用 default_factory。
>
> 版本注：`list[str]` 这种参数化泛型语法从 Python 3.9 起支持；3.8 及以前必须用 `typing.List[str]`。

**field() 函数的全部选项**（重绘表 5.3）：

| 参数 | 作用 | 默认值 |
|------|------|--------|
| `default` | 字段的默认值 | `_MISSING_TYPE`（哨兵值，表示未提供，这样才能把 None 当作真正的默认值） |
| `default_factory` | 生成默认值的无参函数、类或可调用对象 | `_MISSING_TYPE` |
| `init` | 是否将该字段包含在 `__init__` 参数中 | True |
| `repr` | 是否在 `__repr__` 中包含该字段 | True |
| `compare` | 是否在比较方法（`__eq__`、`__lt__` 等）中包含该字段 | True |
| `hash` | 是否在 `__hash__` 中使用该字段 | None（表示跟随 compare：compare=True 时才参与） |
| `metadata` | 用户自定义数据的映射；@dataclass 忽略此参数 | None |

`default` 参数为什么存在？因为注解里 `field(...)` 调用占据了「默认值」的位置，想设默认值只能写在 field() 里：

```python
@dataclass
class ClubMember:
    name: str
    guests: list = field(default_factory=list)
    athlete: bool = field(default=False, repr=False)    # 默认 False，且从 __repr__ 中排除
```

### 4.3 初始化后处理：__post_init__

生成的 `__init__` 只做一件事：把传入的参数及其默认值赋给实例属性。若初始化还需要做更多——**验证**、**根据其他字段计算字段值**——就实现 `__post_init__`；它存在时，会在生成的 `__init__` 的**最后一步**被调用：

```python
from dataclasses import dataclass
from club import ClubMember

@dataclass
class HackerClubMember(ClubMember):
    all_handles = set()             # 类属性（所有实例共享）
    handle: str = ''                # 可选字段，默认空串

    def __post_init__(self):
        cls = self.__class__        # 获取实例所属的类
        if self.handle == '':
            self.handle = self.name.split()[0]      # 计算：默认取姓名的第一部分
        if self.handle in cls.all_handles:
            msg = f'handle {self.handle!r} already exists.'
            raise ValueError(msg)                   # 验证：handle 必须唯一
        cls.all_handles.add(self.handle)
```

doctest 演示预期行为：

```python
>>> anna = HackerClubMember('Anna Ravenscroft', handle='AnnaRaven')
>>> leo = HackerClubMember('Leo Rochael')
>>> leo
HackerClubMember(name='Leo Rochael', guests=[], handle='Leo')     # 自动生成 handle
>>> leo2 = HackerClubMember('Leo DaVinci')
ValueError: handle 'Leo' already exists.                          # 唯一性验证生效
>>> leo2 = HackerClubMember('Leo DaVinci', handle='Neo')          # 显式指定 handle 即可
```

注意生成的 docstring：`"HackerClubMember(name: str, guests: list = <factory>, handle: str = '')"`——`<factory>` 表示该字段默认值由某个可调用对象（本例是 list 类）产生。字段顺序继承自 ClubMember，因此想传 handle 而不传 guests，**必须用关键字参数**。

> 设计提示（书中）：创建具有层次结构的数据类通常是坏主意（超类不是抽象类时滥用继承的问题见第 14 章）。此处用继承只是为了减少代码、聚焦 handle 的声明与验证逻辑。

### 4.4 带类型的类属性：ClassVar

若用 Mypy 检查 4.3 的代码，会报错 `Need type annotation for "all_handles"`。但**不能**给它加普通类型提示——@dataclass 会把 `set[...]` 注解当成实例字段，使 all_handles 变成每实例一份！Mypy 在这里的提示帮不上忙。

正确做法是用伪类型 `typing.ClassVar`：

```python
from typing import ClassVar

@dataclass
class HackerClubMember(ClubMember):
    all_handles: ClassVar[set[str]] = set()      # 类属性，@dataclass 不会为它生成实例字段
```

含义：all_handles 是一个类属性，类型为由字符串构成的 set，默认值为空集。

@dataclass 通常不关心注解中的类型，只有两种例外：**ClassVar**（不生成实例字段）和 **InitVar**（见下节）。

### 4.5 仅初始化的变量：InitVar

有时需要向 `__init__` 传递一个「不作为实例字段」的参数（文档给出的例子：需要从数据库初始化，因此必须把数据库对象传给构造函数）。dataclasses 提供伪类型 `InitVar`：

```python
from dataclasses import dataclass, InitVar

@dataclass
class C:
    i: int
    j: int | None = None
    database: InitVar[DatabaseType | None] = None    # 仅初始化变量

    def __post_init__(self, database):               # 必须为它添加对应的形参
        if self.j is None and database is not None:
            self.j = database.lookup('j')

c = C(10, database=my_database)
```

InitVar 的三个要点：**不是实例属性**、**不出现在 `dataclasses.fields()` 返回的列表中**、但**是生成 `__init__` 的参数**，且会被传递给 `__post_init__`。

### 4.6 综合示例：都柏林核心模式（Resource 类）

都柏林核心模式（Dublin Core Schema）是一组术语，可用于描述数字资源（视频、图像、网页）与实物资源（书籍、CD）等对象，共定义了 15 个可选字段，书中示例实现了其中 8 个：

```python
from dataclasses import dataclass, field
from typing import Optional
from enum import Enum, auto
from datetime import date

class ResourceType(Enum):
    BOOK = auto()
    EBOOK = auto()
    VIDEO = auto()

@dataclass
class Resource:
    """媒体资源描述"""
    identifier: str                                     # 唯一的必需字段
    title: str = '<untitled>'                           # 首个带默认值的字段 → 其后所有字段都要有默认值
    creators: list[str] = field(default_factory=list)
    date: Optional[date] = None                         # 值为 datetime.date 实例或 None
    type: ResourceType = ResourceType.BOOK              # Enum 提供类型安全的值
    description: str = ''
    language: str = ''
    subjects: list[str] = field(default_factory=list)
```

使用：

```python
>>> description = 'Improving the design of existing code'
>>> book = Resource('978−0−13−475759−9', 'Refactoring, 2nd Edition',
...                 ['Martin Fowler', 'Kent Beck'], date(2018, 11, 19),
...                 ResourceType.BOOK, description, 'EN',
...                 ['computer programming', 'OOP'])
>>> book
Resource(identifier='978−0−13−475759−9', title='Refactoring, 2nd Edition',
         creators=['Martin Fowler', 'Kent Beck'], date=datetime.date(2018, 11, 19),
         type=<ResourceType.BOOK: 1>, description='Improving the design of existing code',
         language='EN', subjects=['computer programming', 'OOP'])
```

生成的 `__repr__` 勉强可用。想要「每字段一行、缩进对齐」的格式，可以自定义——核心是用 **`dataclasses.fields(cls)` 遍历字段**：

```python
def __repr__(self):
    cls = self.__class__
    cls_name = cls.__name__
    indent = ' ' * 4
    res = [f'{cls_name}(']
    for f in fields(cls):                        # 遍历数据类的各字段
        value = getattr(self, f.name)            # 按字段名从实例取值
        res.append(f'{indent}{f.name} = {value!r},')
    res.append(')')
    return '\n'.join(res)
```

输出：

```python
Resource(
    identifier = '978−0−13−475759−9',
    title = 'Refactoring, 2nd Edition',
    creators = ['Martin Fowler', 'Kent Beck'],
    date = datetime.date(2018, 11, 19),
    type = <ResourceType.BOOK: 1>,
    description = 'Improving the design of existing code',
    language = 'EN',
    subjects = ['computer programming', 'OOP'],
)
```

> **可复用套路**：`fields(cls)` + `getattr(self, f.name)`——凡是需要「通用地遍历数据类字段」的场景（自定义 repr、序列化、转表格、字段 diff），都用这个组合。

## 五、数据类导致的代码异味（5.7 节）

### 5.1 什么是「代码异味」

Martin Fowler 与 Kent Beck 在《重构》第 2 版中提出了「代码异味（Code Smell）」目录——**代码中可能需要进行重构的模式**。其中专门有一条叫「Data Class」：

> 「数据类」是指那些只包含字段、读写字段的方法，除此之外没有其他功能与逻辑。这样的类被称为「愚蠢的数据持有者」，只用于存储数据，并被其他的类以过于详细的方式进行操作。

Fowler 强调两点：
- **有异味不代表代码一定有问题**——异味是「问题的表征」，是容易被嗅到的表面迹象，你必须更深入地研究、判断是否存在潜在问题；
- 看到数据类时，请自问：**「这个数据类需要什么样的行为？」**然后开始重构、为其加入需要的行为——「通常，简单的思考和基本的重构，是将空洞的对象转变为真正具有功能的类的关键一步」。

**为什么这件事重要**：面向对象编程的主要思想是把**行为和数据**放在同一个代码单元（类）中。若一个类被广泛使用、自身却没有什么重要行为（方法），处理其实例的代码就会分散（甚至重复）在整个系统中——这样的系统对维护来说简直就是噩梦。这就是 Fowler 在重构数据类时，会将责任放回数据类中的原因。

> **记忆要点**：数据类是把双刃剑——构建器让编写它极其容易，而「容易」恰恰会诱使你滥用。用它之前先问一句：这些数据真的不需要行为吗？

### 5.2 两种正当的使用场景

**场景一：脚手架（Scaffolding）**——为快速启动新项目/模块而先实现的临时骨架。例如社交媒体应用先创建一个只有用户名和年龄的 User 数据类；「发送消息」「添加好友」等功能暂时用其他类的方法实现。随着项目发展，应逐步把功能完善进 User 类，使其能独立实现这些功能，最终移除脚手架（或保留继续使用）。

**场景二：中间表述（Intermediate Representation）**——构建要导出为 JSON 或其他交换格式的记录，或保存刚刚跨系统边界导入的数据。要点：

- 三种构建器都提供「实例 → dict」的方法/函数（`_asdict()` / `asdict()`），而 dict 用 `**` 展开即可调用构造函数——这样的 dict 非常接近 JSON 记录；
- 此时应把实例当作**不可变对象**处理——即使字段可变，也不要在它处于中间形式时修改；需要更改值时，应实现自己的构建器方法，而不是直接用 `asdict` 或标准构造函数。

## 六、模式匹配类实例（5.8 节）

模式匹配不仅能匹配序列（2.6 节）与映射（3.3 节），还能匹配**任意类的实例**——类模式（Class Pattern）的匹配对象不仅是数据类，任何类实例都可以。三种类模式：简单、关键字、位置。

### 6.1 简单类模式

语法看起来像构造函数调用。匹配一个 float 实例（无需绑定变量，case 主体中可直接引用 x）：

```python
match x:
    case float():              # 注意此处的 ()，匹配一个 float 实例
        do_something_with(x)
```

**危险写法**（很可能导致 bug）：

```python
match x:
    case float:                # 危险！！！这会匹配任何对象
        do_something_with(x)
```

因为 `case float:` 中 Python 把 float 视为**变量**（捕获模式），并把它绑定到匹配对象——于是任何东西都能匹配成功。

`float(x)` 这种「看似构造函数参数」的写法是一个**特例，仅适用于 9 种内置类型**（PEP 634 列出）：`bytes`、`dict`、`float`、`frozenset`、`int`、`list`、`set`、`str`、`tuple`。对这些类型，括号里看似参数的变量（如 `float(x)` 中的 x）会**绑定整个匹配的实例**；若是子模式，则绑定匹配对象的一部分：

```python
case [ str(name), _, _, (float(lat), float(lon)) ]:
# 匹配项数为 4 的序列：第 1 项必须是 str 实例、最后一项必须是含 2 个 float 实例的二元组
```

除这 9 种内置类型之外，括号里的「参数」表示**实例属性**（见 6.2）。

### 6.2 关键字类模式

```python
import typing

class City(typing.NamedTuple):
    continent: str
    name: str
    country: str

cities = [
    City('Asia', 'Tokyo', 'JP'),
    City('Asia', 'Delhi', 'IN'),
    City('North America', 'Mexico City', 'MX'),
    City('North America', 'New York', 'US'),
    City('South America', 'São Paulo', 'BR'),
]

def match_asian_cities():
    results = []
    for city in cities:
        match city:
            case City(continent='Asia'):                  # 匹配 continent 为 Asia 的 City，其他属性不管
                results.append(city)
    return results

def match_asian_countries():
    results = []
    for city in cities:
        match city:
            case City(continent='Asia', country=cc):      # cc 是「模式变量」，被绑定到 country 属性值
                results.append(cc)
    return results
```

模式变量的命名**没有任何限制**——甚至可以与实例属性同名：

```python
case City(continent='Asia', country=country):
    # 等号左侧的 country 是实例属性名，右侧是模式变量
    results.append(country)
```

关键字类模式可读性很高，并且适用于任何具有公开（public）实例属性的类，不过有些繁琐。

### 6.3 位置类模式与 __match_args__

```python
def match_asian_cities_pos():
    results = []
    for city in cities:
        match city:
            case City('Asia'):                 # 匹配第一个属性值为 'Asia' 的 City
                results.append(city)
    return results

def match_asian_countries_pos():
    results = []
    for city in cities:
        match city:
            case City('Asia', _, country):     # 第 3 个属性绑定到模式变量 country
                results.append(country)
    return results
```

「第几个属性」的顺序由特殊类属性 **`__match_args__`** 决定——本章的类构建器都会**自动创建**它：

```python
>>> City.__match_args__
('continent', 'name', 'country')
```

位置模式中属性的顺序，就是 `__match_args__` 中声明的顺序。

> **记忆要点**：`__match_args__` 列出的只是**可供匹配的实例属性，而不是全部属性**——所以有时候需要在同一个模式中**混用**关键字模式与位置模式。

## 七、杂谈：PEP 526 对 class 语句约定的冲击（5.10 节）

书末「杂谈」记录了作者对 @dataclass 语法的吐槽，很有意思，也解释了这套语法为什么让人感觉有点「别扭」：

- **@dataclass 强制要求类型提示**——过去 7 年间 PEP 484 一直承诺「类型提示永远是可选的」，现在这个重要功能却必须提供类型提示。对静态类型趋势不感兴趣的人，可以考虑用 attrs 库替代 @dataclass；
- **PEP 526 颠覆了 class 语句的既定约定**：以前在 class 块顶层声明的所有内容都是类属性（方法也是类属性）；有了 @dataclass 之后，顶层声明且带类型提示的属性都变成了**实例属性**：

```python
@dataclass
class Spam:
    repeat: int                 # 实例属性

@dataclass
class Spam:
    repeat: int = 99            # 还是实例属性

@dataclass
class Spam:
    repeat = 99                 # 没有类型提示 → 又变成类属性！

@dataclass
class Spam:
    repeat: ClassVar[int] = 99  # 想声明"带类型的类属性"→ 必须用伪类型 ClassVar
```

- 作者希望实现的新语法（用 `.` 前缀标识实例属性）：

```python
@dataclass
class HackerClubMember:
    .name: str                          # 带 . 前缀 → 实例属性
    .guests: list = field(default_factory=list)
    .handle: str = ''
    all_handles = set()                 # 不带 . 前缀 → 类属性（像以前一样）
```

「真希望我能将 Guido 的时间机器借来一用，回到 2017 年，让 Python 核心团队采纳我的想法。」（小彩蛋：Jargon File 的 Guido 词条说他有台时光机——因为用户的新功能请求常得到回复「我昨晚刚实现了这个」。）

## 本章总结

### 核心概念速查表

| 概念 | 一句话定义 |
|------|-----------|
| 数据类 Data Class | 只作为字段集合、几乎没有额外功能的简单类 |
| collections.namedtuple | 工厂函数，构建带字段名的 tuple 子类；内存开销与 tuple 相同 |
| typing.NamedTuple | 带类型提示的具名元组，支持 class 语法（3.6+），由元类实现 |
| @dataclass | 类装饰器（3.7+），默认可变、功能最全、不影响类的层次结构 |
| 类型提示 Type Hints | 运行时无效的「文档」，供 Mypy/IDE 静态检查；import 时进入 __annotations__ |
| PEP 526 变量注解 | `var: type = value` 语法；在数据类中同时承载字段类型与默认值 |
| field() | dataclass 字段级定制：default、default_factory、repr、compare、hash… |
| default_factory | 为可变字段（list/dict/set）生成默认值的无参可调用对象 |
| __post_init__ | 生成的 `__init__` 的最后一步调用；用于验证与计算字段 |
| ClassVar | 伪类型：声明类属性，@dataclass 不当它是实例字段 |
| InitVar | 伪类型：仅初始化变量，进 `__init__` 与 `__post_init__`，不进实例 |
| __match_args__ | 位置类模式的属性顺序表，类构建器自动生成 |
| 代码异味 Code Smell | 深层设计问题的表面迹象——纯数据类就是其中一条 |

### 最佳实践清单

1. **先问「它需要行为吗」**：数据类适合脚手架与中间表述；纯数据类扩散到系统各处就是设计问题；
2. 选择构建器：轻量记录 → `collections.namedtuple`；要类型提示 → `typing.NamedTuple`；要可变实例/默认值工程/更多控制 → `@dataclass`；
3. 可变默认值（list/dict/set）**必须**用 `field(default_factory=list)`，不要写 `= []`；
4. 想不可变、可哈希（进 set / 当 dict 键）→ `@dataclass(frozen=True)`；想排序 → `order=True`；
5. 类属性用 `ClassVar[类型]`；非字段的构造参数用 `InitVar[类型]` + `__post_init__` 形参；
6. 通用遍历字段用 `dataclasses.fields(cls)` + `getattr`，不要硬编码字段名；
7. 从实例造新实例：具名元组用 `_replace()`，dataclass 用 `dataclasses.replace()`；
8. 需要验证/转换/更多功能时考虑 **attrs**；需要运行时数据验证时考虑 **pydantic**；
9. 数据类实例用于导入/导出（中间表述）时，把它当不可变对象处理。

### 常见坑 Top 5

1. **`case float:`（漏掉括号）会匹配任何对象**——模式匹配中 float 被当作变量，必须写 `case float():`；
2. **`guests: list = []` 会让模块导入直接抛 ValueError**——可变默认值必须用 default_factory；
3. **给类属性加类型提示却忘了 `ClassVar`**——@dataclass 会把它错误地变成实例字段；
4. **默认（frozen=False）的 dataclass 不可哈希**——`__hash__` 被置为 None，不能进 set / 当 dict 键；
5. **以为类型提示会检查运行时值**——`Coordinate('Ni!', None)` 照跑不误，要靠 Mypy 等静态工具提前发现。

2. `C = namedtuple('C', 'x y')`，`c = C(1, 2)` 后：`c[0]`、`c.x`、`C._fields` 分别是什么？
3. `class Coordinate(NamedTuple)` 中，`NamedTuple` 是超类吗？给出验证代码。
4. 标注为 float 的字段被传入字符串，为什么运行时不报错？什么工具能发现？
5. `@dataclass class ClubMember: guests: list = []` 会发生什么？如何修正？
6. `frozen=True` 与 `order=True` 各带来什么能力？实例「可哈希」的条件是什么？
7. `__post_init__` 在何时被调用？两个典型用途是什么？
8. 为什么 `all_handles` 要用 `ClassVar[set[str]]` 而不是 `set[str]`？InitVar 的作用呢？
9. 模式匹配中 `case float:` 与 `case float():` 的致命区别？
10. 位置类模式的属性顺序由什么决定？如何查看？

**参考答案**

1. 关键是**可变性**：namedtuple 与 NamedTuple 都是 tuple 子类、不可变；@dataclass 默认可变，且不依赖继承/元类、定制性最强。轻量记录用前两者（要类型提示选 NamedTuple），需要可变实例/默认值工厂/冻结/排序等控制时用 @dataclass。
2. `c[0]` 与 `c.x` 都得 1（可按位置或字段名访问）；`C._fields` 得 `('x', 'y')`。
3. 不是。它出现在超类位置，实际上是元类机制在定制类的创建——`issubclass(Coordinate, typing.NamedTuple)` → False，`issubclass(Coordinate, tuple)` → True。
4. 因为类型提示在运行时完全无效（只被记录进 `__annotations__`）。Mypy 等静态类型检查器能在运行前发现类型不匹配并报 error。
5. 加载类时抛 `ValueError: mutable default <class 'list'> for field guests is not allowed: use default_factory`。修正：`guests: list = field(default_factory=list)`。
6. `frozen=True`：实例不可变，赋值/删除字段抛 `FrozenInstanceError`；`order=True`：生成 `__lt__`/`__le__`/`__gt__`/`__ge__`，实例可排序。可哈希条件：`eq=True`（默认）且 `frozen=True` → 生成 `__hash__`；默认 `frozen=False` 时 `__hash__` 为 None（不可哈希）。
7. 在生成的 `__init__` 的**最后一步**被调用；用于验证（如 handle 唯一性）与根据其他字段计算字段值（如自动生成 handle）。
8. 普通类型提示（`set[str]`）会被 @dataclass 当作实例字段，每个实例都会得到该属性；`ClassVar` 明确告诉 @dataclass「这是类属性、跳过它」。`InitVar` 用于声明只传给 `__init__`/`__post_init__` 而不作为实例属性保存的构造参数（如数据库对象），它不出现在 `dataclasses.fields()` 的返回值中。
9. `case float:` 中 float 被 Python 当作变量名（捕获模式），会匹配任何对象并把它绑定到 float；`case float():` 才匹配 float 的实例。
10. 由类属性 `__match_args__` 决定（类构建器会自动生成，如 `City.__match_args__` → `('continent', 'name', 'country')`）。用 `类名.__match_args__` 查看；关键字类模式不受此限制，它直接按属性名匹配。

## 延伸阅读精选（书中 5.10 节浓缩）

- **PEP 557 – Data Classes**：@dataclass 的源头文档。有三节未被复制进模块文档，值得一读：「为何不直接使用 namedtuple」「为何不直接使用 typing.NamedTuple」「Rationale（基本原理）」——后者明确回答了「什么时候不适合使用数据类」：
  - 需要兼容 tuple 或 dict 的 API 时；
  - 需要超出 PEP 484 和 526 提供的类型验证时，或者需要值验证或转换时。
- **Geir Arne Hjelle《Data Classes in Python 3.7+ (Guide)》**（RealPython.com）：非常完整的指南文章；
- **Raymond Hettinger 的 PyCon US 2018 演讲**《Dataclasses: The code generator to end all code generators》；
- **attrs 项目**（Hynek Schlawack）：比 dataclasses 更早、功能更多（验证、转换器等），承诺「把你从实现对象协议的繁重工作中解脱出来」；PEP 557 的作者 Eric V. Smith 承认 attrs 对 @dataclass 的影响——包括最重要的 API 决策：用装饰器（而不是基类和/或元类）完成工作；
- **Dave Beazley 的 cluegen**：另一个数据类生成器，其 README 展示了「提供解决方案而不是工具」的理念；
- **《重构：改善既有代码的设计》第 2 版**（Martin Fowler）：数据类「代码异味」的最佳来源；第 2 版示例使用现代 JavaScript（更接近 Python），对 Python 爱好者很友好；
- 书外补充：
  - **PEP 681 – dataclass_transform**（3.11+）：让 attrs、pydantic 等第三方库能声明「本库构建的类具有 dataclass 语义」，从而被类型检查器识别；
  - **pydantic**：提供运行时数据验证与序列化的现代方案，广泛用于 FastAPI 等框架——与 @dataclass 的「编译期检查、运行时不检查」正好互补。
